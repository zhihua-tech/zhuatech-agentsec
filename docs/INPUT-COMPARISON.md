## 本项目核算

**工具批准版本与失效时间核对**。沿用 [原算法及字段契约](OPERATIONS-REVIEW.md)，不另造简化算法，不调用外部模型，也不读取业务数据库。两组输入都按当前算法独立校验和重算；不是对历史结果文件作可信比较。

本项目对照样例（虚构）：当前请求参数版本改为4。具体断言见 `backend/src/test/resources/operations/comparison-cases.json`，覆盖本项目所有有效业务边界样例及原值/新值断言，原有无效输入回归仍保留。

## 页面操作

1. 打开 `/comparison.html`，使用现有企业账号；JWT 也可复用原登录令牌，不新增本地凭据存储。
2. 分别录入基准、候选两组数据和核对日期。编号不区分大小写，重复编号拒绝整批；新增/移除记录按编号识别。日期不同会提示可比性。
3. 对照后查看变化类型、建议变化、逐字段原值/新值及精确十进制差值。筛选和分页不影响全量CSV/JSON导出。文本、日期、N/A不会被猜成数字。
4. 修改任何业务输入都会隐藏旧结果；规则版本不符返回409，需刷新版本后重算。
5. 原 `/operations.html` 和对照页均可导出**输入快照**。对照页导入JSON，先在服务器完整校验，再经用户确认整体替换一组；校验失败或取消时原输入、原有效报告保持不变。每组页面最多100条，不截断超量文件。

## 接口与版本

全部沿用现有后端身份认证，不接受匿名请求；不访问别人的业务记录，也不新增审批/执行权限。所有成功与业务错误响应 `Cache-Control: no-store`。

| 方法 | 路径（前缀 `/api/operations-review`） | 用途 |
| --- | --- | --- |
| GET | `/comparison-contract` | 字段、样例、项目标识及契约/算法指纹 |
| POST | `/compare` | `{expectedRuleFingerprint, baseline:{asOf,records}, candidate:{asOf,records}}` |
| POST | `/import-check` | 校验版本化输入快照；只返回整组已验证输入，不存盘 |

快照结构：`{format:"zhuatech-review-input/v1",project,contractFingerprint,ruleFingerprint,scenario:{asOf,records}}`。项目不符、报告文件、重复JSON键、未知字段或任一业务行无效返回400；字段契约不符409；旧算法输入允许导入并返回 `ruleChanged:true`，重算永远使用当前算法；比较请求规则指纹过期409。未认证401，错误不包含堆栈或凭据。

`contractFingerprint` 是原 `schema.json` 字节摘要；`ruleFingerprint` 同时包含该摘要和现有核算服务字节码摘要（重新编译也可能变化）。输入摘要按字段键排序，但保留记录顺序及输入文本形式；数字文本与数字JSON值可能摘要不同。指纹不是数字签名，不证明输入真实或曾审批。返回操作人、UTC时间和关联号来自服务器，仅用于本次响应追踪，**不是持久化审计日志**。

## 边界、安全与测试

- HTTP和文件最多256KiB；严格UTF-8、JSON重复键/尾随数据检测；深度8、节点15000；两组后端合计最多500条，同时受字节和节点上限约束。页面每组1至100条。
- 所有原业务约束继续生效；任一无效输入导致整批失败，不能静默跳行。快照仅是输入，不接受客户端自报的历史核算结果。
- 精确十进制差由Java BigDecimal计算并以文本传递；CSV转义公式型单元格，导出文件仍可能含业务信息，需要调用者妥善保管。
- 建议较宽松可能只是门槛放宽，不代表实际风险降低。系统不审批、付款、合并代码、调度Agent或控制设备。
- 新增服务、真实HTTP身份验证、版本冲突、导入原子失败及前端纯函数测试，同时运行原有回归与前端生产构建；认证集成使用隔离H2测试环境。未声明完成40套MySQL生产部署、压测、全业务端到端或全系统生产认证。
- 未修改原非商业许可、数据库结构、生产账号或部署密钥。实际部署继续遵循原项目HTTPS、访问控制和敏感配置要求。
